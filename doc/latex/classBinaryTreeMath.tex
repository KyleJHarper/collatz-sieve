\doxysubsection{Detailed Description}
\subsubsection*{template$<$\mbox{\hyperlink{conceptAnySupportedIntegral}{Any\+Supported\+Integral}} T$>$\newline
class Binary\+Tree\+Math$<$ T $>$}
The core algorithms supporting tree building and navigation. 

\begin{DoxyAttention}{Attention}
This class contains many of the core formulas driving the entire algorithm behind the custom {\ttfamily \doxylink{classBinaryTree}{Binary\+Tree}}.
\end{DoxyAttention}
The math behind any \doxylink{classBinaryTree}{Binary\+Tree} must support the two types of coordinates consistently. These are\+:
\begin{DoxyItemize}
\item Levels are the vertical coordinates and are labeled with countering numbers\+: 1, 2, 3 ...
\item Positions are the left-\/to-\/right horizontal coordinates and are labeled with counting numbers\+: 1, 2, 3 ...
\end{DoxyItemize}

As shown, 0-\/based indexes are not used for tree coordinates. They could be, but it just sounds weird to call the first level of a tree "{}level zero"{}. More importantly, it also requires more +1/-\/1 adjustments in the functions. Levels were zero-\/based originally, but this was changed in version 3.\+0.\+0.

The math for building a {\ttfamily \doxylink{classBinaryTree}{Binary\+Tree}} supports both 0-\/ and 1-\/based trees. In the original research, trees rooted at zero were fine because manual research was still underway into patterns. Patterns aligned more cleanly with a tree rooted at one, and it also meant the tree contained the space of \doxylink{classCollatz}{Collatz} Conjecture correctly (no zero). Therefore, 1-\/based trees became the defaul as of version 2.\+0.\+0. That said, 0-\/based trees are still possible by changing {\ttfamily Binary\+Tree\+Math\+::set\+\_\+root\+\_\+value(0)}, however their performance and behavior is provided on a best-\/effort basis and might be removed later.

The cumulative magnitude required to scale a parent node {\ttfamily N} to its descendants on the target level. 

When a given node {\ttfamily N} is singled out, it creates a subtree. To find all the leaf nodes on level {\ttfamily L} that are rooted by node {\ttfamily N}, three things are required\+:


\begin{DoxyEnumerate}
\item The cumulative magnitude to reach the smallest leaf node. This function provides that.
\item The scaling factor to iterate over leaf nodes in order. The {\ttfamily \doxylink{classBinaryTreeMath_a910ad0174fe5fa88139e71cba7629bb1}{st\+\_\+scaling\+\_\+factor()}} provides that.
\item The number of leaf nodes, which is simply 2\texorpdfstring{$^\wedge$}{\string^}(target\+\_\+level -\/ base\+\_\+level)
\end{DoxyEnumerate}

Therefore, this function let\textquotesingle{}s you find all the first (smallest) values of the leaf nodes on a {\ttfamily target\+\_\+level} of any position on {\ttfamily base\+\_\+level}. From there, you simply iterate by the scaling factor.

\begin{DoxyParagraph}{Formula}
$ 2^{(target\_level - 1)} - 2^{(base\_level - 1)} $
\end{DoxyParagraph}
\begin{DoxyNote}{Note}
This function is used with node VALUES, not POSITIONS. Position arithmetic differs. 
\end{DoxyNote}
