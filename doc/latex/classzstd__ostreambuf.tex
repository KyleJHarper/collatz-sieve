\doxysubsection{Detailed Description}
A {\ttfamily streambuf} subclass which wraps the C-\/style ZSTD bits to create a compressed stream.

Constructor which requires a destination stream. 

This implementation uses the {\ttfamily ZSTD\+\_\+create\+CCtx} and takes a few liberties.

First, it will attempt to use the number of threads as indicated by {\ttfamily std\+::hardware\+\_\+concurrency()}. If 0 or negative is returned, it is set to 1. If greater than 16 is returned, it is clamped to 16.

Next, when compression level is over 19, long-\/distance matching is enabled. This drastically improves the compression ratio at the expensive of CPU-\/time (it\textquotesingle{}s slower).

Finally, when compression level is over 19, it also switches to the {\ttfamily ZSTD\+\_\+e\+\_\+flush} end-\/directive. Normally, ZSTD waits for a full window of data before waking up its compressor threads. The flush directive forces compression immediately. This class uses an input buffer size of 16MB to help optimize compressor work. The whole reason for switching to flush is to help ZSTD engage more worker threads. Without this, compression was observed to get choked down to a single thread and process very slowly.

\begin{DoxyParagraph}{Compliance}

\end{DoxyParagraph}
The data emitted by this class should be a fully compliant ZSTD file. Meaning, if written to disk, any other ZSTD compliant program can read it, including the {\ttfamily zstd} CLI.

Flush all remaining buffers and wait for ZSTD to say its finished. 

ZSTD needs all input flushed to it (obviously), but it also requires the caller to check {\ttfamily ZSTD\+\_\+e\+\_\+end} when in multi-\/threaded mode until it reports 0. There\textquotesingle{}s some ZSTD frame bits (checksums maybe?) that isn\textquotesingle{}t fully understood, but this cycling is mandatory before calling any destruction, implicit or otherwise.
