void \mbox{\hyperlink{classGPUVerifier}{GPUVerifier}}$<$ T $>$\+::run\+\_\+executor (\begin{DoxyParamCaption}{ }\end{DoxyParamCaption})\hspace{0.3cm}{\ttfamily [inline]}, {\ttfamily [virtual]}}



The actual implementation of verification steps, with necessary template params/constexpr values sent. 

Unlike the {\ttfamily GPUVerifier\+\_\+\+\_\+\+Old}, this method does not use the tree iterator whatosever. It loops over the surviving values and sends them to the \doxylink{namespaceGPU}{GPU} along with a {\ttfamily \doxylink{classBinaryTree}{Binary\+Tree}\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}::st\+\_\+scaling\+\_\+factor()} and an internal multiplier, allowing the both the CPU and \doxylink{namespaceGPU}{GPU} to mimic the {\ttfamily \doxylink{classBinaryTree}{Binary\+Tree}\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}::for\+\_\+each\+\_\+uncovered\+\_\+value\+\_\+with\+\_\+tls()} infinite iteration.

Why? Because it allows this method to send larger work sets to the \doxylink{namespaceGPU}{GPU} by asking it to scale all survivor root-\/values on its own in a loop. This takes pressure off the CPU iterator and PCIe bus, amortizing the cost of host-\/device synchronization.

\begin{DoxyNote}{Note}
The {\ttfamily \doxylink{classNodeBitmap}{Node\+Bitmap}} assures all values sent in a {\ttfamily For\+Each\+Policy\+::\+PARALLEL} mode will never skip more than one prefix\textquotesingle{}s worth of range if one or more threads issues a premature {\ttfamily For\+Each\+Signal\+::\+BREAK}. This method would normally violate that contract by allowing that range to expand due to the {\ttfamily scales\+\_\+per\+\_\+run} factor. To protect against this, this method will simply issue a {\ttfamily For\+Each\+Signal\+::\+CONTINUE} when the {\ttfamily \+\_\+end\+\_\+value} is reached, guaranteeing ALL survivor values are buffered. The only downside is the {\ttfamily scales\+\_\+per\+\_\+run} will mean verification can go beyond the {\ttfamily \+\_\+end\+\_\+value}. All of this will be accurately reflected in the metrics.
\end{DoxyNote}

\begin{DoxyParams}{Parameters}
{\em scales\+\_\+per\+\_\+run} & Controls the number of times a scaling factor is applied to a surviving value on the \doxylink{namespaceGPU}{GPU} side. During a normal {\ttfamily tree.\+for\+\_\+each\+\_\+uncovered\+\_\+value()} an internal {\ttfamily multiplier} is incremented and applied to a {\ttfamily scaling\+\_\+factor}, which results in value-\/ordered enumeration of suviving values using simple arithmetic. Unfortunately, this requires the CPU to read, store, and then transmit values to the \doxylink{namespaceGPU}{GPU}, which also overloads the PCIe bus. This method skips the tree iterator and iterates over the surviving root values ONLY and tracks multipliers and the scaling factor directly. By passing these to the \doxylink{namespaceGPU}{GPU}, it can do large "{}runs"{} of a surviving value\textquotesingle{}s subtree nodes. This amortizes the CPU work (buffering root values) and the PCIe load. The only downside is that extremely large {\ttfamily scales\+\_\+per\+\_\+run} will keep the \doxylink{namespaceGPU}{GPU} busier for longer inside an uninterruptable operation, which means pausing, stopping, or other tear-\/down might take extra time. \\
