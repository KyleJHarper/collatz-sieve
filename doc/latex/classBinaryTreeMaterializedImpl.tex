\doxysubsection{Detailed Description}
\subsubsection*{template$<$\mbox{\hyperlink{conceptAnySupportedIntegral}{Any\+Supported\+Integral}} T$>$\newline
class Binary\+Tree\+Materialized\+Impl$<$ T $>$}
An implementation of the {\ttfamily \doxylink{classBinaryTree}{Binary\+Tree}} which creates and persists {\ttfamily \doxylink{classNode}{Node}} objects in memory. 

This is the materialized version, which creates real \doxylink{classNode}{Node} objects and persists them. When pruning is enabled, nodes which hit the High-\/\+Water Mark (HWM) are removed, leaving only nodes which still need to be tested.

\begin{DoxyNote}{Note}
This was a first-\/principles implementation when starting out. It\textquotesingle{}s great for in-\/memory inspection of true {\ttfamily \doxylink{classNode}{Node}} objects, or when you want to walk an actual tree, but RAM explodes quickly. If you need to work with larger trees, consider using the {\ttfamily \doxylink{classBinaryTreeImplicitImpl}{Binary\+Tree\+Implicit\+Impl}} instead.
\end{DoxyNote}

Add a level to the tree. 

Materialized tree building happens by taking the nodes from the last level in {\ttfamily \+\_\+level\+\_\+map} and treating them as parents. The children created have known values according to Harper\textquotesingle{}s algorithm. The children are checked for High-\/\+Water Mark, and stored in the next level of the map.

When HWM pruning is anbled, all grandparents who meet HWM are trimmed, which prevents entire subtrees of nodes from taking up memory.

When parent level pruning is enabled, all parents are trimmed, which keeps only the last level of nodes in memory. \Hypertarget{classBinaryTreeMaterializedImpl_a6d7c5d9d4a3626fb564bb8f16a4ab4b2}\label{classBinaryTreeMaterializedImpl_a6d7c5d9d4a3626fb564bb8f16a4ab4b2}
