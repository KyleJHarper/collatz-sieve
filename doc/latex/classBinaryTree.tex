\doxysubsection{Detailed Description}
\subsubsection*{template$<$\mbox{\hyperlink{conceptAnySupportedIntegral}{Any\+Supported\+Integral}} T, typename Tree\+Type = Binary\+Tree\+Implicit\+Impl$<$\+T$>$$>$\newline
class Binary\+Tree$<$ T, Tree\+Type $>$}
The \doxylink{classBinaryTree}{Binary\+Tree} facade which will apply Harper\textquotesingle{}s sieve of AST nodes. 

This static facade will build a binary tree using the child values (labels) defined in Harper\textquotesingle{}s research, which will find and remove any nodes whose FG-\/chain reaches the Abort at Stopping Time condition, eliminating subtrees.

Users may choose the {\ttfamily \doxylink{classBinaryTreeMaterializedImpl}{Binary\+Tree\+Materialized\+Impl}} or the {\ttfamily \doxylink{classBinaryTreeImplicitImpl}{Binary\+Tree\+Implicit\+Impl}}.

The {\ttfamily \doxylink{classBinaryTreeMaterializedImpl}{Binary\+Tree\+Materialized\+Impl}} is a true, memory-\/backed tree with nodes connected via edges (pointers). It is extremely heavy in RAM, but its saving grace is that it\textquotesingle{}s a true binary tree which users can walk and analyze. If pruning is enabled, nodes are removed according to the pruning policy, leaving what is technically a directed acyclic graph (DAG).

The {\ttfamily \doxylink{classBinaryTreeImplicitImpl}{Binary\+Tree\+Implicit\+Impl}} is a mathematically equivalent tree, and is the default as of version 4.\+0.\+0. It uses significantly less memory by foregoing nodes in favor of a {\ttfamily \doxylink{classNodeBitmap}{Node\+Bitmap}} which tracks the uncovered positions\+: the leaf node positions of the tree which haven\textquotesingle{}t been pruned by an AST ancestor yet.

Assert non AST verification is enabled when necessary. 

If verification is disabled (default) and the tree level exceeds the max known, fail. It might seen annoying, but the API refuses to allow people to build trees beyond empirically tested bounardaries unless they are willing to verify non AST nodes themsleves. The limit is defined by {\ttfamily \doxylink{namespaceCollatzConstants_a973af5204c6bff2e94087a73f2b4af0c}{Collatz\+Constants\+::\+LARGEST\+\_\+\+EMPIRICALLY\+\_\+\+TESTED\+\_\+\+LEVEL}}.

\begin{DoxyParagraph}{Deeper Explanation}

\end{DoxyParagraph}
When building a tree, the nodes which don\textquotesingle{}t meet AST (directly or by ancestor) need to be checked. For example, the number {\ttfamily 14} is below the AST because of the {\ttfamily G} step on node {\ttfamily 2}. Its value becomes {\ttfamily 7}. That node isn\textquotesingle{}t an AST node, descendant of one, nor has it been verified by the tree. This leaves pockets of nodes that aren\textquotesingle{}t verified, which means the overall AST value of the tree isn\textquotesingle{}t valid.

To compensate, verification can be activated via the {\ttfamily \doxylink{structBinaryTreeOptions}{Binary\+Tree\+Options}} during {\ttfamily \doxylink{classBinaryTree_a2eeaf4a7727c29a727d01845add1475b}{init()}}, or by calling {\ttfamily \doxylink{classBinaryTree_a32c3e51017d9f421ffa6828575955973}{enable\+\_\+non\+\_\+ast\+\_\+node\+\_\+verification()}} on an instantiated tree. However, external work by \href{https://link.springer.com/article/10.1007/s11227-025-07337-0}{\texttt{ David Barina}} has empirically verified up to {\ttfamily 2\texorpdfstring{$^\wedge$}{\string^}71}, which is the first node on level {\ttfamily 72} of a tree. Ergo, nodes up through level {\ttfamily 71} are verified and do not need re-\/verification.

\begin{DoxyWarning}{Warning}
This is an assertion, not a boolean. It will throw if verification is disabled and level count grows beyond limits. 
\end{DoxyWarning}
